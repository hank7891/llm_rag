# Ch10 實驗紀錄：Citation（來源對應與顯示）

檢索：bge-m3、Top-K 5、門檻 > 0.59。LLM：qwen3:8b（Ollama，num_ctx 8192，think 關閉）、gpt-4.1-mini。

## 引用寫法樣本與解析規則

Ch09 的 7 份結果（30 題 × 2、推理題 13 題 × 3、d03 × 3）中，回答裡實際出現的方括號：

| 寫法 | 次數 |
| --- | --- |
| `[1]`～`[5]`（含連寫 `[1][2]`、`[1][3][4][5]`） | 110 |
| `[資料不足]` | 1 |
| `[1, 3]`、`[1、3]`、`[1-3]`、全形 `［１］` | 0 |

最終規則（`CitationParser`）：

- 標記：半形 `[]` 或全形 `［］`，內容 1～20 字、不含換行；超過 20 字的方括號視為一般文字（例如引述條文名稱）。
- 內容先以 `mb_convert_kana('a')` 把全形英數字轉半形，再判斷是否為編號：`數字（分隔符 數字）*`，分隔符為 `,`、`，`、`、`；範圍為 `-`、`–`、`~`、`～`、`－`，展開成多個編號（反向或超過 20 的範圍只取起點）。
- 不是編號的內容（`[資料不足]`、`[來源]`）為 non_numeric。
- 合法的編號一律改寫為 `[n]` 連寫：`［１、３］` → `[1][3]`；`[1, 9]` 中只有 9 不合法時改寫為 `[1]`。
- 移除標記後，清掉標記前多出的空白：「未提及 [資料不足]。」→「未提及。」。

## 設計決策（照建議實作）

1. **`insufficient_by_llm` 改為「以資料不足開頭」**：Ch09 用「含有」判斷，r08 這類「先回答前半、最後說後半資料不足」的回答會被歸為資料不足，依 3.3 規則連帶清空前半的合法來源。原建議為「等於」，實作時放寬為「開頭」：Ch09 的純拒答多半是「資料不足。參考資料中未提及……」這種先下結論再說明的形式。換句話說的拒答（「無法回答」「並未提及」）仍判斷不到。
2. **兩份測試集都跑**：`questions.jsonl`（30 題）＋ `reasoning.jsonl`（13 題），新舊 Prompt × 2 Provider，共 8 輪。
3. **舊 Prompt 保留為 `resources/prompts/rag-answer-v1.md`**，以環境變數 `RAG_ANSWER_SYSTEM_PROMPT=prompts/rag-answer-v1.md` 執行，未修改 `.env`。
4. **實驗 3 的 Prompt 變體只放在 scratchpad 的一次性腳本**，不進入 repo。
5. 資料不足的回答中被移除的編號另以 `insufficient_answer` 記錄（任務文件的三種原因之外新增），用來觀察 Prompt v2「資料不足時不要加任何編號」是否生效。

## 實驗 3：讓模型自己寫來源（對照組）

一次性腳本（scratchpad，不進入 repo）：參考資料每段前面附上「檔名｜條號｜頁碼」，要求模型在回答後逐行寫出「來源：檔名｜條號｜頁碼」，再與本次參考資料的實際值比對。抽 10 題（q01、q03、q04、q05、q07、q09、q12、q15、q17、q19）。

| | 來源行數 | 正確 | 條號錯 | 頁碼錯 | 檔名不存在 |
| --- | --- | --- | --- | --- | --- |
| qwen3:8b | 13 | 12 | 1 | 0 | 0 |
| gpt-4.1-mini | 13 | 13 | 0 | 0 | 0 |

- 錯誤案例：qwen3:8b q12 寫成「員工差勤管理規章.pdf｜**第第二章** 請假 / 第五條｜第 3 頁」（複製時多了一個字）。
- q19 兩家都寫「資訊設備盤點公告.txt｜第 1 頁」：這份文件沒有條號，省略是對的；腳本一開始要求三個欄位而誤判為「未寫來源」，已人工更正。
- **比 Ch04 準確得多**：Ch04 長 Context 時兩家都標錯頁碼（qwen3:8b 第 5 頁、gpt-4.1-mini 第 25 頁），因為頁碼標記離答案很遠；這次檔名、條號、頁碼就緊貼在每一段前面，模型只需要照抄。
- **但仍不應交給模型**：
  1. 照抄也會抄錯（「第第二章」），而且錯誤看起來和正確的來源一樣；程式產生的來源錯誤率是 0。
  2. 模型寫的是一段文字，無法驗證它是不是本次參考資料中真的存在的那一段；編號則可以檢查範圍並向 MySQL 查證。
  3. 寫出來的來源和回答中的句子沒有對應關係；`[n]` 標在句末，才知道哪一句引用了哪一段。
  4. 每題多花輸出 Token。

## 實驗 5：Ch09 q08 再檢查

Ch09 的案例：qwen3:8b 回答「若需申請工資，可透過人事系統提交相關申請，並保留好相關紀錄，以備查核 [2]」。[2]（差勤規章第四條）是合法編號、MySQL 查得到、也屬於檢索結果，所以**本章程式會把它顯示為來源**；但原文是「公司保存作業紀錄供主管機關查核」，回答改成「員工自己保留紀錄」。

**引用存在 ≠ 引用正確**：CitationResolver 只能確認「編號合法、來源存在」，無法判斷句子是否被引用內容支撐。命中率也只看段落對不對。這類錯誤要靠人工抽查，或下一階段的 Faithfulness 評估。

v2 Prompt 重問同一題（`rag:ask --show-context`）：回答「雇主應發給相應的工資 [1][3]……雇主亦應發給工資 [1]」，[3] 為差勤規章第四條的後半段，原文確實有「特別休假因年度終結……雇主應發給工資」，這次有依據、沒有延伸。Ch09 的錯誤沒有重現，但如實驗 2 所述，這是隨機性，不代表問題已解決。
