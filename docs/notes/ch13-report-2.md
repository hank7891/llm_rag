## 補充說明：`--answer` 與 `--window` 的關係（重新說明）

`rag:eval-conversation` 在每題做兩件獨立的事：

1. **檢索評估**（一定會做）：由 `ConversationEvaluator` 自己組 Window、自己改寫、自己檢索。這一段的 Window 輪數由 `--window` 決定。
2. **完整問答**（加 `--answer` 才做）：把同一份腳本化歷史交給 `RagAnswerService`，走正式的問答流程。正式流程的 Window 只讀設定檔的 `rag.conversation.window_turns`（目前 3），**不受 `--window` 影響**。

所以 `--window=5 --answer` 時，檢索評估用 5 輪，但量 input_tokens 的完整問答仍用 3 輪，兩者不一致。目前 `--answer` 只用來量回答 LLM 的最大 input_tokens，所以實驗 4 都沒有加 `--answer`，只有「開啟 Reranker 的 C」加了。如果之後把 window_turns 改成 5，要改 `.env` 再重跑 `--answer`。
