## 2. 新的改寫狀態 unchanged

- **判斷方式**：去掉空白、標點與符號（`\s`、`\p{P}`、`\p{S}`）後，改寫結果和原問題相同。
  - 檢索用原問題，`called = true`。
  - 存入 `conversation_messages.rewrite_status_key` 與 `rag_query_logs`，欄位長度足夠，不需要 migration。
- **評估報告**：成本表新增「改寫結果與原問題相同（unchanged）」題數。
- **限制**：只多一個字也算 rewritten。例如 qwen3 v1 在 h14 輸出「…是**由**誰負擔？」，實際上沒有補任何對象，仍被記為 rewritten。
- **測試**：3 種情況（完全相同、只差空白與標點、有補上對象）。已做反向驗證：拿掉判斷後測試會失敗。

### think 開啟的代價

- **改寫耗時**：
  - p50 28 秒、p95 70 秒。
  - 最快約 20 秒（原樣輸出的完整問題也要先思考），最慢 70 秒（h01，含模型首次載入）。
- **整體等待**：回答 LLM 在這台機器約 10～57 秒，加上改寫等於每次追問多等一倍以上。
- **逾時設定**：
  - 原本的 30 秒會讓大約一半的題目逾時降級，這次實驗用 120 秒。
  - 如果採用 think，`rewrite.timeout` 至少要 90～120 秒，`config/llm.php` 的 Ollama timeout（120 秒）也要一起考慮。
- **thinking 不會混進改寫結果**：
  - 實測 Ollama 開啟 think 時，`message.thinking` 與 `message.content` 分開回傳。
  - `OllamaProvider::chat()` 只讀 `message.content`，所以思考內容不會進入改寫結果。
- **只透過 provider_options 修改**：
  - `rag:eval-conversation` 新增 `--rewrite-think=on|off`，覆寫 `rag.conversation.rewrite.provider_options.ollama.think`，QueryRewriter 不需要修改。
  - 另外新增 `--rewrite-timeout=`。
