# Ch05 總結：Chunking（結構優先的切段）

## 成果

```
解析完成（parsed）→ 自動派送 ChunkDocumentJob
  → parsed → chunking（樂觀鎖）
  → PageTextAssembler：依頁碼串成全文，建立 Offset Map（每頁的起訖字元位置）
  → StructureSplitter：依「第 X 章」「第 X 條」、Markdown 標題切出結構段落，記錄 section
  → RecursiveSplitter：過長的段落依 段落 → 換行 → 句子 → 字元 切小，切開處以句子重疊
  → 以起訖位置反查 page_start / page_end
  → Transaction：刪除舊 Chunk → 寫入 document_chunks → chunked
```

工具：`php artisan rag:chunk {id} --strategy= --max-tokens= --overlap=`（重新切段）、`rag:chunks {id}`（列表與統計）；文件檢視頁的「切段結果」分頁。實驗紀錄見 `ch05-experiments.md`。

## 結構優先切法

- **規章適合「一條一段」**：一條規定語意完整，引用來源可以直接標示條號（section 例如「第二章 請假 / 第三條之一」）。實驗中固定大小切法把 37/49 條切成兩半、44/46 段在句子中間結束；結構優先只有 3 條因本身超過上限而被迫切開。
- **章標題不放進內容**，只作為其下各條的 section；相鄰的短條文不合併。
- **條文標題 vs 內文引用**：標題必須是「第 X 條」或「第 X 條之 Y」，後面只能接空白或換行；「第三條之一規定辦理」是引用。這套判斷集中在 `StructureMarkers`，Ch03 的 Normalizer（接回硬換行）與切段共用，避免兩邊不一致。
- **條名只在同一行明確寫出時採用**：下一行的短句無法可靠區分是條名還是正文。

## Recursive Chunking

- 先用大的邊界（空行），切不下才用更小的邊界（換行 → 句子 → 字元）。
- 只有單一單元仍超過上限才往下切；並且**收掉的內容太短（例如只有標題）時，與下一個單元一起往下切**，避免產生只有標題的 Chunk。
- 過短的尾段以原文範圍併回前一段（不會重複文字），合併後超過上限就保留。
- 全程只操作字元位置、不重組文字：Chunk 內容一定等於原文切片，頁碼反查才準確。PHP 正規表示式回傳 byte 位置，必須換算成字元位置。

## Overlap 的使用時機

- **只用在同一段落被迫切開的位置**：條與條之間、段落之間不需要重疊（它們本來就是完整的語意單位）。
- **以句子對齊**：取上一段尾端連續的完整句子，總長 ≤ 上限的 15%，並且計入 Chunk 的長度上限。最後一句就超過預算時不重疊，不跳過它去拿更前面的句子。
- 重疊的目的是避免重要資訊剛好被切在兩段之間；代價是重複的內容會佔用 Embedding 與 Context 的空間。

## 跨頁頁碼的處理

- 切段在**串接後的全文**上進行，跨頁的條文才能成為同一個 Chunk；每個 Chunk 記錄在全文中的起訖位置，再用 Offset Map 查出所在頁碼。
- 邊界規則：頁與頁之間的換行算上一頁；終點剛好在頁尾時不算跨頁；空白頁不參與查詢。
- 實驗抽查 15 個跨頁 Chunk，開頭與結尾的頁碼全部與原始 PDF 一致。

## Chunk 大小與連動限制

| 限制 | 說明 |
| --- | --- |
| **太大** | 混進不相關的內容，檢索不準（向量被稀釋）；每段佔用更多 Context |
| **太小** | 語意不完整，答案被切散；Chunk 數量變多，檢索與索引成本增加 |
| **Embedding 輸入上限** | bge-m3 為 8192 Token，超過時會截斷且不一定報錯；600 遠低於上限 |
| **Context 預算** | Top-K × Chunk 長度 + System Prompt + 回答空間 ≤ num_ctx。以 Top-5 估算最壞約 4,300 Token，低於 8,192 |
| **Tokenizer 差異** | 切段用保守係數（中文每字 1.0）估算；qwen3 實測約 0.75，bge-m3 於 Ch06 實測後校正 |

上限要依文件的單一條文長度決定：這份長文件一條約 300～650 Token，上限 400 時 44/49 條被切開，800 時全部完整。

## 狀態與工程設計

- 新增 `chunking`、`chunked` 狀態（與 `parsing`、`parsed` 相同模式）：切段進度可見；以樂觀鎖防止兩個切段 Job 同時執行；`parsed → indexing` 改為不允許（沒切段不能建索引）；`chunked → chunking` 允許（調整參數後重新切段）。
- 解析與切段是兩個 Job：切段失敗不影響已保存的頁面，也可以單獨重跑。
- **冪等重建**：重新切段一律在同一個 Transaction 內先刪除舊 Chunk 再寫入；寫入失敗時舊 Chunk 完整保留。
- **參數外部化**：`config/rag.php`；每個 Chunk 記錄 `chunk_strategy`（例如 `structure_v1:max600:ov15`），Ch08 比較設定時用。
- **`content` 保存原文**，不加前綴；章節資訊放在 `section` 欄位。是否在 Embedding 時加上章節前綴，Ch06 再決定。

## 過程中修正的前面章節問題

- Ch03 Normalizer：行首的內文引用被當成條文標題、清單項目的續行接不回去、頁碼行比對沒有統一空白（第 10 頁以後的頁尾沒被移除）。
- Ch04 長文件樣本：版面溢出裁掉 10 條，改寫產生腳本並重新產生（新版 19 頁、49 條；Ch04 實驗使用的是舊版）。

這些問題都是在**準備或檢查本章的資料時**才浮現：真實的排版會產生各種邊界情況，樣本要刻意涵蓋，實驗結果也要回頭懷疑資料本身。
