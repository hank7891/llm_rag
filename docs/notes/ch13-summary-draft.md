  - 改寫結果看起來合理，但主題是錯的，改寫狀態仍是 rewritten，系統沒有任何錯誤或降級訊號。
  - N = 1 時被對到筆電；N = 5 時才正確命中工作規則第一條。

## 改寫 LLM 會把無意義的輸入補成上一輪的主題

- 在 `rag:chat`（conversation 2）中送出「x」，qwen3:8b 把它改寫成「服務滿二年以上未滿三年者的特別休假天數是多少？」，也就是上一輪的主題。
- 回答 LLM 看的是原問題「x」，所以回答「資料不足」；但檢索用的是幻覺出來的問題，如果回答 LLM 也拿改寫後的問題（實驗 5 的另一種做法），就會回答一個使用者沒問的問題。
- 改寫的驗證（空白、過長、像答案）攔不到這種情況：輸出格式完全正常。這也是回答階段送「原始問題」的理由之一。
- 該輪紀錄已刪除（2026-10-09）。

## 對小模型來說，規則越多不一定越好

- qwen3:8b（think 關閉、N = 3）：v1（教學文件原文兩行）Recall@1 64%，v2（多四條規則）57%。
- v2 修好了編號保留（h12），卻讓其他題原樣輸出（h11、n02），並把括號例子「表單編號」抄進改寫結果（h01）。
- 每加一條規則都可能在別的題目產生副作用，修改 Prompt 後一定要重跑整份 `rag:eval-conversation`，不能只看針對的那一題。

## 改寫產生的泛用詞會讓 Dense 分數普遍上升

- n01（無答案）：「那員工宿舍呢？」不改寫時 Dense 最高 0.5595，低於門檻 0.59，判斷為無候選。
- OpenAI 改寫成「請問公司有提供員工宿舍的**相關規定或資訊**嗎？」，Dense 升到 0.5978，超過門檻，變成「有候選」並呼叫回答 LLM（只剩第二道防線）。
- 「相關規定」「資訊」這類泛用詞和任何規章段落都有點像，會把分數普遍往上推；而 Dense 門檻是用單輪的使用者原始問題校準的（Ch08）。
- 改寫後的問題分布和校準時不同，門檻的效果會改變。如果改寫上線後無答案題被放行的比例上升，需要用改寫後的問題重新校準門檻，或在 Prompt 中禁止加入泛用詞。
