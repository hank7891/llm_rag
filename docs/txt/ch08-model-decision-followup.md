# Ch08 補充任務：Embedding 模型決定與門檻補測

> 接續：`ch08-agent-task.md` 第 5.6 節（Embedding 模型比較）
> 完成本檔後，回到 `ch08-agent-task.md` 第 6 節（四項實驗）繼續，最後依第 8 節回報。

## 一、決定

**線上採用 bge-m3**，`company_docs_bge_m3` 維持為線上 Collection。

- `.env` 不需修改
- `qwen3-embedding:0.6b` 的 Collection **保留不刪**，供 backlog 實驗對照
- 兩個模型的門檻值維持目前設定（bge-m3 0.59、qwen3 0.48），本檔的補測結果出來後再決定是否調整

決定理由（寫入 `docs/notes/`）：

1. 換句話說題 Recall@1 為 92% 對 58%，排序明顯較準
2. 門檻兩群間隔 0.044 對 0.021，門檻較穩定
3. 記憶體約 1/3、建索引速度較快，在 16GB 機器上需與 qwen3:8b 同時執行
4. qwen3 在 Recall@10 多命中的題目屬精確編號類，將交由 Hybrid Search 階段處理

## 二、補測原因

「正確段落進入 Context」這一項，bge-m3 為 19/24，低於 qwen3 的 21/24。

bge-m3 的 Recall@5 約為 23/24，但只有 19 題通過門檻，代表約 4 題有答案的問題被 0.59 的門檻擋掉。下一階段接上 LLM 後，這些題目會直接回答「資料不足」。

需要確認被擋掉的是哪類題目：

- 精確編號題：可接受，Hybrid Search 階段會補上
- 換句話說題：門檻偏高的代價落在語意搜尋最重要的題型上，需要重新取捨
