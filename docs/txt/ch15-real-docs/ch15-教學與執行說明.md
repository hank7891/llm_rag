## 一、本章定位

第一階段的數字（門檻 0.59、Recall@5 96%、無答案 6/6 擋下）都建立在 **30 題、76 個 Chunk** 的自製人資文件上。大綱已經寫明：門檻是暫定值，要換上真實文件重跑。

這一章**不加新功能**，只做三件事：

1. 換上一批真實、量較大、結構較複雜的文件，確認整條資料流（上傳 → 解析 → 切段 → 向量化 → 檢索）沒有在新資料上默默壞掉
2. 用新的測試集（71 題）重跑 Ch08／Ch11／Ch12 的評估，產出一份「同一把尺、新的資料」的比較表
3. 依新的分數分布**重新決定門檻值**，並把結論寫成有條件的數字

一句話：**第一階段證明流程可行，這一章證明那些數字在真實資料上還成立（或找出不成立的地方）。**

`laws/*.md` 是從全國法規資料庫擷取的純文字版，每份都已用 SHA-256 與網站原文比對一致。它的角色是**標準答案與覆核依據**，不一定是你要上傳的檔案（見第四節階段 1）。

### 刻意不放進來的法規

政治獻金法、地方制度法、中央選舉委員會組織法、政黨法都和選舉高度相關，**刻意不收**。它們的主題會出現在無答案題（例如「政治獻金上限」「縣市長任期」），用來測試系統在「看起來很相關、其實文件沒寫」時能不能說資料不足。之後要擴充，先把對應題目從 `no_answer` 改掉。

> 公民投票法施行細則有兩個版本：93 年行政院版（pcode D0020051）已於 107 年廢止，現行的是 107 年中選會訂定版（D0020080）。搜尋時兩個都會出現，不要拿錯。

## 三、這批文件會打到哪些既有設計

這是本章真正的知識點。第一階段的每個設計都在人資文件上驗證過，換資料後要逐項確認。

### 1. 雙胞胎條文（最重要）

總統選罷法與公職選罷法有大量幾乎逐字相同的條文：投票所禁帶手機、民調封關十日、每日活動 7 時到 22 時、選票攜出罰一萬五千元、重新計票千分之三……公投法也有一部分。

- **檢索端**：向量幾乎一樣，誰排第一近乎隨機。Recall 看起來正常，**引用的法規卻是錯的**。
- **評估端**：原本的 Recall 只問「有沒有找到正確 Chunk」，現在要多看一個指標——**文件層級正確率**（Top-1 的法規名稱對不對）。
- **真正會出錯的是差異處**：例如緩刑者能否登記參選，公職選罷法 115 年修法加了但書（宣告緩刑者不在此限），總統選罷法沒有（緩刑期間不得登記）。測試集 D11 與 F02 就是在考這一對。

### 2. 條號格式

| 寫法 | 出現在哪 |
| --- | --- |
| `第 63-1 條` | 全國法規資料庫的條號標題（官方 PDF 亦同） |
| `第63條之1` | 一般人提問、第一階段 Ch11 的精確詞抽取 |
| `第六十三條之一`、`第九十七條第一項` | **條文本文裡的交叉引用一律用國字** |
| 選罷法、總統選罷法、公投法 | 口語簡稱，文件裡從不出現 |

影響：Ch11 的 MySQL FULLTEXT（ngram）只比對字面，使用者打「第97條」不會命中本文的「第九十七條」；打「選罷法」也不會命中「公職人員選舉罷免法」。這不一定要在本章修，但**一定要量出來**（測試集 C 類）。

### 3. 階層與「款」的雙重意義

公職選罷法第三章是 `章 → 節 → 款 → 條`，例如「第九節 罷免 / 第一款 罷免案之提出 / 第 75 條」。但條文內的「第一款」又是指列舉項目。Ch05 若用「第 X 款」當切段邊界或 section 標題，會誤切。另外還有 `第 四 章 （刪除）` 這種空章名夾在節與節之間。

### 4. 長度兩極

| | 例 | 字數 |
| --- | --- | --- |
| 最長 | 公職選罷法施行細則第 15 條（登記表件） | 1,681 |
| | 公職／總統選罷法第 26 條（不得登記之情事） | 約 1,050 |
| 最短 | 「（刪除）」共 15 條 | 4 |
| | 「本細則自發布日施行。」 | 10 |

- 長條文：依 Ch06 實測 bge-m3 約 0.68 Token／字，1,681 字約 1,150 Token，要確認沒有超過 Ch05 的上限、也沒有被 Reranker 的最大長度截掉後半（Ch12 的靜默截斷）
- 短條文：「（刪除）」這種 Chunk 沒有任何資訊，但短查詢可能跟它算出不低的分數。要不要索引是一個決定點（見交接文件）

### 5. 分數分布會被壓縮

法規用語高度均質（「選舉委員會」「應於……日內」「處……有期徒刑」），很多 Chunk 彼此相似。預期現象：

- Top-1 與 Top-2 的分數差距變小，排序更依賴 Reranker
- 無答案題的最高分可能**比第一階段高**（領域內的無答案題尤其如此），0.59 可能擋不住
- 有答案的短查詢可能掉到門檻以下

所以門檻不能沿用，要重新掃描，而且要**分類別看**。

### 6. 文件內容與模型記憶衝突

| 規定 | 舊（模型可能記得的） | 現行 |
| --- | --- | --- |
| 公投日 | 8 月第 4 個星期六，每兩年一次（108 年版） | 公告成立後 3～6 個月內，期間內有全國性選舉應同日舉行（114-12-03） |
| 緩刑者參選縣市長 | 緩刑期間不得登記 | 宣告緩刑或得易服社會勞動者不在此限（115-07-01） |
| 罷免提議 | 不需附身分證影本 | 應附國民身分證正反面影本（114-02） |
| 投票時間 | 模型常答「上午 8 點到下午 4 點」 | 法律只說由選舉公告載明，條文中沒有時間 |

本章只**記錄**模型在這些題目上有沒有照文件回答，不評分、不修 Prompt。這些紀錄就是下一章 Faithfulness 的起點。

### 7. 規模

Chunk 數大約從 76 變成 480～550。索引時間、Qdrant 查詢、Hybrid 的 FULLTEXT 候選數都會變，`rag:stats` 的 p50／p95 要重記一次基準。

## 四、執行步驟

整章分 7 個階段，每個階段結束都有一個要你確認的停止點。交接給 Agent 的版本見 `ch15-agent-handoff.md`。

### 階段 0：準備

1. 確認在 `ch14-done` 上，開新分支 `ch15-real-docs`
2. **先備份 `docs/notes/`**（大綱 backlog 第一項還沒做，這章會產生大量新報告，先處理掉）
3. 用 v1 測試集（第一階段 30 題）在現況跑一次 `rag:eval`，存成 `docs/notes/ch15-baseline-v1.md`。這是換資料前的最後一張快照
4. 決定舊人資文件的去留（停止點 ①，見交接文件）

### 階段 1：取得文件與解析驗收

1. 在你的電腦執行 `bash scripts/download_official_pdfs.sh`，下載 7 份官方 PDF
2. 打開每份 PDF 第一頁，確認「修正日期」與 `laws/manifest.csv` 一致
3. 上傳 7 份 PDF，等全部變成 `indexed` **之後**再叫 Agent 做下一步（Ch11 的教訓：讓 Agent 收到指令時資料已經就位）
4. Agent 匯出 Chunk（document_name、section、content），執行
   `python3 scripts/check_article_coverage.py chunks.json laws/expected_articles.json`
5. 判讀重點：
   - 每部法規條數對得上（不含刪除：12／123／42／145／62／56／22）
   - 沒有「多出不存在的條號」——出現代表 pdftotext 把頁首頁尾或交叉引用誤判成條號標題
   - 抽 5 個 Chunk 與 `laws/*.md` 逐字比對，特別看跨頁的條文（PDF 換頁處最容易斷句或夾雜頁碼）

**為什麼用 PDF 而不是直接上傳 .md**：Ch03 的整條解析路徑（pdftotext、逐頁、Normalizer）是為 PDF 寫的，重新校準要連解析一起驗。.md 版留作答案與比對來源。如果解析問題太多、影響本章進度，可以先改用 .md／.txt 跑完評估，解析問題另開 backlog（停止點 ②）。

### 階段 2：Chunking 量測（不改策略）

只量，不改。輸出：

- Chunk 總數、每部法規的 Chunk 數
- 長度分布（p50、p95、最大），對照 Ch05 上限與 Reranker 最大長度
- 被切成多段的條文清單（第 26 條、細則第 15 條應該在裡面）
- section 欄位格式抽樣：是否有章／節／款資訊、`63-1` 怎麼存
- 「（刪除）」條文有沒有變成 Chunk

若發現切段錯誤（例如以「款」為邊界誤切），**先回報、不要自行修**。修 Chunking 會改變所有分數，要在基準跑完後才能動，一次只改一個變因。

### 階段 3：測試集定稿

`testset/ch15_election_testset_v1.jsonl` 是 71 題草稿：

| 類別 | 題數 | 考什麼 |
| --- | --- | --- |
| single 單一條文 | 19 | 基本問法 |
| paraphrase 換句話說 | 13 | 口語、情境式（「我剛搬家要去哪投票」） |
| exact_ref 精確條號 | 7 | 簡稱、國字條號、`之1` |
| confusable 跨法易混淆 | 11 | 雙胞胎條文、題目限定選舉種類 |
| temporal 修法時效 | 4 | 文件與模型記憶衝突 |
| multi_hop 多條組合 | 5 | 需要 2～3 條才答得完整 |
| no_answer 無答案／部分答案 | 10 | 領域內陷阱、領域外、時事 |
| false_premise 錯誤前提 | 2 | 題目本身說錯 |

定稿要做的事：

1. **你親自看過每一題**（CSV 版方便用試算表看）。題目是我依條文寫的，不是真實使用者問的，口語程度可能不夠
2. 確認 `expected` 的條號寫法與系統 section 欄位能對上（`63-1` vs `第63條之1`），由 Agent 寫對應規則，不要改測試集
3. 想到的真實問法直接加，目標 80～100 題（大綱的建議量）
4. 定稿後**凍結**，之後所有調參都用同一份。改題目等於換尺，前後數字不能比

> 評分規則：`expected` 列了多個條文時，Recall@k 以「任一命中」計；同時另記「全部命中」給 multi_hop 用。B02、B04 這類雙胞胎題，兩部法律都算對。`answerable` 為 `no` 的題目看是否被門檻擋下；`partial` 的題目檢索要命中所列條文，回答要說明文件沒寫的部分。

### 階段 4：基準評估

固定以下設定，依序跑三組，**每組設定只差一個開關**：

| 組 | 檢索 | 重排 | 門檻 |
| --- | --- | --- | --- |
| E1 | Dense | 關 | 不套用（先看原始分數） |
| E2 | Hybrid（RRF k=60） | 關 | 不套用 |
| E3 | Hybrid | bge-reranker-v2-m3，候選 20 → Top 5 | 不套用 |

每組都要輸出：

- Recall@1、Recall@5、MRR，**分類別**
- **文件層級 Top-1 正確率**（新指標），以及雙胞胎混淆矩陣：總統法 ↔ 公職法 ↔ 公投法互相拿錯幾次
- 每題 Top-5 的 chunk、法規、條號、分數（原始資料存 JSON，報告只放摘要）
- 檢索 p50／p95

### 階段 5：門檻重新校準

1. 以 Gate 實際使用的分數（依 Ch11 設計應是 Dense 分數，請 Agent 先從程式確認，不要假設）畫兩組分布：
   - 有答案題：正確 Chunk 的分數
   - 無答案題：Top-1 分數
2. 門檻從 0.40 到 0.75、間隔 0.01 掃描，每個值記錄：有答案題被誤擋數、無答案題放行數
3. 選值原則（先寫下來再看結果，避免看完數字才定規則）：
   - 無答案題（`no`）擋下率 ≥ 90%
   - 在上述前提下，有答案題誤擋最少
   - 兩群分數若重疊，**不要硬選一個漂亮的數字**，回報重疊區間與落在裡面的題目
4. 與 0.59 並列比較：舊門檻在新資料上擋了誰、放了誰
5. `partial` 類題目單獨列出，不納入選值計算

### 階段 6：端到端抽測與判讀

用 E3 設定加新門檻，挑 8 題實際問答，Ollama 與 OpenAI 各跑一次，**只記錄不評分**：

## 五、注意事項

### 資料與版本

- 法規會修正，這批文件是 2026-11-23 的版本。報告與測試集都要寫明版本日期；之後法規再修，用 `manifest.csv` 的雜湊比對就知道哪部要更新
- 2026-11-28 是地方公職人員選舉投票日，選舉前後條文不太可能變，但新聞與網路資料很多，**不要讓 Agent 從網路補資料或補題目**，所有標準答案都以 `laws/*.md` 為準
- 系統回答的是條文內容，不是法律意見。真實選務問題應以中選會公告為準，展示時要說清楚

### 評估紀律（延續第一階段的心得）

- **一次只改一個變因**。本章唯一的實驗變數是「換資料」，Chunking、Prompt、模型、Hybrid 參數一律不動；發現問題記 backlog
- **條件不同的數字不能排在同一條序列裡**。v1（人資 30 題）和 v2（選舉 71 題）的 Recall 不能直接比高低，只能各自和自己的前後版本比
- **指標要成對看**。Recall@5 不變但文件層級正確率下降，代表雙胞胎問題；Recall 上升但無答案放行也上升，代表門檻太鬆
- **任何上限都要實測**。長條文的 Token 數、Reranker 截斷，用實際 Chunk 量，不要用字數推估
- **判讀結果也要被判讀**。Agent 報告的結論，至少抽 3 題回到原始 JSON 核對

### 與 Agent 協作

- 上傳完、確認 `indexed` 才回覆 Agent
- 停止點一定要停：舊文件去留、解析策略、測試集定稿、門檻值，都由你決定
- 規則寫進 CLAUDE.md／AGENTS.md：測試集凍結、標準答案以 `laws/*.md` 為準、不從網路補資料
- 要求證據：Agent 說「解析正常」，要附 coverage 檢查的輸出；說「門檻建議 0.6x」，要附掃描表

### 中立性

測試題只問程序與規則，不涉及特定政黨、候選人或政治立場。之後自己加題目時也維持這個原則，避免測試集本身帶有立場。
